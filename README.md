# karukan-skkserv

English | [日本語](README.ja.md)

> [!WARNING]
> This project was generated by AI. The owner is still reading through the code and cannot guarantee that it works correctly.

An skkserv-compatible dictionary server powered by the kana-kanji conversion engine of [karukan](https://github.com/togatoga/karukan).

It receives readings from SKK clients and returns candidates from karukan's AI model and system dictionary. The engine is embedded in the server, so no separate backend is needed.

## Requirements

- Rust 1.92 or later
- A C/C++ compiler, CMake, and libclang (used to build llama.cpp)
- Network access for the first build and first launch (to fetch the karukan source and the model)

## Setup

Build the server:

```sh
cargo build --release
```

Install the system dictionary in karukan's default location:

```sh
curl -fLO https://github.com/togatoga/karukan/releases/latest/download/dict.tgz
mkdir -p ~/.local/share/karukan-im
tar xzf dict.tgz -C ~/.local/share/karukan-im dict.bin
```

Start the server:

```sh
./target/release/karukan-skkserv
```

By default, it listens on `127.0.0.1:1178` and uses EUC-JP. The model is downloaded from Hugging Face on first launch (about 110 MB for the default model). Set `HF_HOME` to change where it is stored. Until the model has loaded, the server returns dictionary candidates only.

To keep the dictionary and model in the repository's `data/` directory, which Git ignores, start it like this:

```sh
HF_HOME=$PWD/data/hf ./target/release/karukan-skkserv --dict data/dl/dict.bin
```

## Client configuration

### ddskk

```elisp
(setq skk-server-host "127.0.0.1"
      skk-server-portnum 1178)
```

### fcitx5-skk

Add this line to `~/.local/share/fcitx5/skk/dictionary_list`:

```text
encoding=EUC-JP,host=127.0.0.1,port=1178,type=server
```

Dictionaries are searched from top to bottom. To show this server's candidates first, place the line right after the `user.dict` line.

### libskk `skk` command

```sh
echo 'K a n j i SPC RET' | skk -s 127.0.0.1:1178 -u /tmp/skk-test.dict
```

Only the libskk `skk` command has been tested. Actual input through ddskk and fcitx5-skk has not been verified.

## Options

| Option                   | Default                | Description                                          |
| ------------------------ | ---------------------- | ---------------------------------------------------- |
| `--host <HOST>`          | `127.0.0.1`            | Address to listen on                                 |
| `-p`, `--port <PORT>`    | `1178`                 | Port to listen on                                    |
| `--encoding <ENCODING>`  | `euc-jp`               | Wire encoding (`euc-jp` or `utf8`)                   |
| `--dict <DICT>`          | karukan's setting      | Path to the system dictionary                        |
| `--model <MODEL>`        | `conversion.model`     | Model key in karukan's `[models]` table              |
| `--no-model`             |                        | Respond from the dictionary only, without the model  |
| `--model-candidates <N>` | `3`                    | Number of model candidates per lookup                |
| `--max-candidates <N>`   | `30`                   | Maximum number of candidates returned per lookup     |
| `--timeout-ms <MS>`      | `2000`                 | Time limit for one model conversion, in milliseconds |
| `--threads <N>`          | `conversion.n_threads` | Number of inference threads                          |
| `--max-connections <N>`  | `32`                   | Maximum number of simultaneous connections           |

Set the `RUST_LOG` environment variable to change log verbosity (default: `info`).

The server has no authentication or encryption. If you use `--host` to bind to a non-loopback address, restrict access to a trusted network.

### karukan configuration

If `~/.config/karukan-im/config.toml` exists, the server reads the same settings as karukan-im. It uses `conversion.model`, `conversion.n_threads`, `conversion.dict_path`, and `[models]`.

The dictionary path is resolved in this order: `--dict`, `conversion.dict_path`, then `~/.local/share/karukan-im/dict.bin`. If the dictionary cannot be loaded, the server runs without one.

## Conversion behavior

- **Candidate order:** Model candidates come first, followed by dictionary candidates, with duplicates removed. For keys without okurigana, the katakana form is added last.
- **When the model is unavailable:** While the model is loading, or after a timeout or conversion error, the server returns candidates without model results. These responses are not cached.
- **Okurigana:** `かk` is converted as `かく`, and the stem `書` is returned.
- **Unsupported keys:** Latin abbreviations, numeric keys containing `#`, and prefix or suffix keys containing `>` always return "not found". Look these up in your personal SKK dictionary or another dictionary.
- **Completion:** The skkserv completion request (`4`) returns readings from the dictionary.
- **Encoding:** Candidates that cannot be represented in EUC-JP, such as emoji, are omitted from the response.
- **Safety:** ddskk evaluates candidates starting with `(` as Lisp. Candidates that start with `(` or contain `/` or `;` are therefore escaped into a `concat` expression of a literal string. Candidates containing control characters are not returned.

## Known issues

- Unnatural candidates such as `hennkann` or `高か` may appear.
- When cycling through okurigana candidates in libskk, the order may differ from what the server returned (for example, `掛` may follow `書`). The cause has not been identified.

## Development

```sh
cargo test
```

`Cargo.toml` pins karukan to a specific commit. To update it, change the `rev` of both `karukan-engine` and `karukan-im` to the same commit, then run:

```sh
cargo update -p karukan-engine -p karukan-im
```

`.cargo/config.toml` stops the llama.cpp build from looking for OpenSSL. It is kept in this repository because Cargo does not apply the configuration of a dependency.
